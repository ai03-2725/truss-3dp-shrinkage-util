# English/Japanese UI — implementation plan

Source of truth: [PRD.md](./PRD.md). Work in `truss-webui/` unless stated otherwise. **Depends on** lists prerequisite task IDs; a parent is complete only after all its subtasks are complete. Follow the order below. Tasks 1–8 deliver the **implementation milestone** (Japanese may contain English placeholders); task 9 is the separate **public-release gate** requiring the maintainer's Japanese translations. Keep the existing Solid/Vite app and calibration behavior; do not add a translation framework or browser-test dependency unless an identified requirement actually needs one.

- [x] **1. Establish the baseline and copy inventory.** Depends on: none. Deliverable: a passing baseline and a map of every user-facing string and its owner. See [copy-inventory.md](./copy-inventory.md).
  - [x] **1.1. Record current behavior.** Depends on: none. From `truss-webui/`, run `pnpm test` and `pnpm build`; record pre-existing failures. Trace `src/App.tsx`, `src/lib/storage.ts`, `src/lib/app-api.ts`, and both flow modules to see where persisted state lives and which screen components remount on language changes.
  - [x] **1.2. Inventory localization surfaces.** Depends on: 1.1. Check `src/pages/`, `src/components/`, `src/App.tsx`, and `src/lib/` for visible copy, alt/caption/title text, aria labels, progress labels, validation/import/export/storage messages, and transient status messages. Note that `src/lib/printers.ts` and `src/lib/storage.ts` currently return English errors, while `ResultPercent` already tracks status as a code. Separate UI text from numeric values, printer names, filenames, and JSON keys, which must remain unchanged.
  - [x] **1.3. Choose small copy boundaries.** Depends on: 1.2. Map each screen to (a) shared state/calculation/validation and required interactive controls, and (b) page-like formatted content that English and Japanese authors may order independently. Plan per-screen content/slot props only where needed; put short shared labels and parameterized errors in locale-specific messages. Verify the map covers Home, About, Manage printers, all Quad/Single steps, shared guides, dialogs, and lightbox.

- [x] **2. Add locale resolution and independent persistence.** Depends on: 1. Deliverable: one reactive locale in the app, chosen correctly before the first screen renders.
  - [x] **2.1. Resolve the initial language.** Depends on: 1.3. Define supported locale IDs (`en`, `ja`) and a small resolver: valid stored manual choice first; otherwise walk `navigator.languages` in order (using `navigator.language` if needed), match base languages such as `ja-JP`, and default to English if none match. Treat an invalid stored value as unset; keep the supported-language list easy to extend.
  - [x] **2.2. Save only manual selections.** Depends on: 2.1. Store the selected locale under its own browser-storage key, not inside `truss-calibrator-v1` or printer export JSON. Catch reads/writes that fail, including unavailable storage, and keep the chosen locale in memory for the current session; browser detection must not overwrite or silently create a manual preference.
  - [x] **2.3. Wire locale into `App.tsx`.** Depends on: 2.2. Initialize the locale synchronously before rendering page copy, expose the current locale and a setter to the screens/switcher, and update `document.documentElement.lang` on initialization and changes. Keep active calibration, printer profiles, and `screen()` independent of locale; selecting a language must not invoke Finish, Exit, or a calibration save.
  - [x] **2.4. Test locale rules.** Depends on: 2.3. Use the existing Node test setup and an injectable/fake storage surface to check saved-choice precedence, ordered supported-language matching, regional variants, unsupported-only/empty preferences, invalid stored values, and storage read/write failures. Confirm existing storage and printer import/export tests still pass.

- [x] **3. Put an accessible selector on every screen.** Depends on: 2. Deliverable: one consistent, immediately applying language control that does not interfere with navigation.
  - [x] **3.1. Build the switcher.** Depends on: 2.4. Add the existing Phosphor globe SVG to `src/lib/icons.ts`. Make a compact icon-button + popover/select control (or equally accessible equivalent) with a localized accessible name and options labeled `English` and `日本語`; selection updates the app locale immediately without an Apply button. Use existing UI primitives/CSS rather than a new popover library.
  - [x] **3.2. Place it on all screens.** Depends on: 3.1. Add the control alongside the Home link icons; add it beside Home on About/Manage printers and beside Exit in `FlowFrame` for every Quad/Single step, including results. Keep existing progress and navigation buttons working; do not inadvertently make selecting a language submit a form.
  - [x] **3.3. Finish interaction and layout.** Depends on: 3.2. Style the control in `src/local.css` for narrow and wide viewports; make keyboard focus, Escape/outside dismissal, touch targets, and focus return predictable. Ensure the top bar can accommodate the Japanese option and step progress without overlap. A modal dialog may need to be closed before using the switcher; preserving unsaved printer-dialog input across a switch is not required.
  - [x] **3.4. Smoke-check switching.** Depends on: 3.3. Switch on Home, About, Manage printers, a mid-flow Quad step, and a result screen. Verify the same screen remains displayed and the selected choice survives refresh when storage works. Check keyboard/touch behavior before converting the rest of the copy.

- [x] **4. Establish page-like English/Japanese authoring with two pilot screens.** Depends on: 3. Deliverable: a proven pattern for separately editable JSX content without duplicated app behavior.
  - [x] **4.1. Create the content convention.** Depends on: 3.4. Add parallel locale-specific TSX content (for example, `src/pages/en/` and `src/pages/ja/`) plus a minimal reactive way for shared screens to select it. Provide per-screen props/slots for functional controls where their placement may differ, rather than duplicating callbacks, calculations, or a universal page-rendering framework. Seed Japanese with the exact English wording as placeholders.
  - [x] **4.2. Convert Home.** Depends on: 4.1. Move card titles/descriptions/conditional hints, link names/tooltips/accessible labels, and surrounding layout copy into the two page-like content versions. Keep the start/open callbacks and disabled Single calibration condition in one shared implementation. Confirm both locale versions can place cards and links as needed without changing what their controls do.
  - [x] **4.3. Convert About.** Depends on: 4.2. Move its formatted long-form instructions, lists, figure alt text, and other copy into parallel JSX content. Preserve the existing image asset, shared navigation, and responsive markup; prove paragraph/figure order can differ per language without changing app state.
  - [x] **4.4. Check the pilot before scaling it.** Depends on: 4.3. Run `pnpm test` and `pnpm build`; compare English Home/About to the baseline and toggle both locales on each screen. Ensure choosing a locale only changes copy/content and document language, with no flash of the wrong locale after a fresh load.

- [x] **5. Localize shared UI and printer management.** Depends on: 4. Deliverable: shared controls, all dynamic non-flow messages, and Manage printers have a locale-aware source of copy.
  - [x] **5.1. Cover shared chrome and guides.** Depends on: 4.4. Localize `FlowFrame` progress/back/next/exit labels, `ConfirmDialog`, `BeamFields`, `NumberField` labels/warnings, `ResultPercent` copy/status, `Guide` text and image descriptions, `Figure` zoom label, and `Lightbox` controls/announcements. Keep static units and all numeric handling unchanged. Use short locale-specific messages for reusable controls and JSX for formatted guidance; avoid English defaults that survive on Japanese screens.
  - [x] **5.2. Make dynamic failures translatable in place.** Depends on: 5.1. Replace English message strings stored as UI state (notably App storage warning, printer form/import errors, and helper-returned validation errors) with stable error identifiers plus any dynamic parameters such as printer name or file version; translate on render so an already-visible error changes language instantly. Preserve the existing validation rules, warnings, JSON shape, and storage-failure behavior; do not parse English text to identify errors. Adapt existing helper tests as needed.
  - [x] **5.3. Convert Manage printers.** Depends on: 5.2. Add separate page-like English/Japanese content for explanatory copy, headings, table labels, button text, import results, preferences, and form/delete dialogs. Keep add/edit/delete/import/export handlers and their data shared; keep unsaved form text preservation out of scope. Confirm error placeholders, plural/count output, and user-entered names render correctly in both locales.
  - [x] **5.4. Check shared and printer states.** Depends on: 5.3. Exercise invalid add/edit/import, duplicate name, storage unavailable, clipboard success/failure, and zoom/lightbox. Switch language while a visible warning or error is present and verify it updates without re-triggering the action. Run `pnpm test` and `pnpm build` before changing the calibration screens.

- [x] **6. Convert the Quad calibration flow in small groups.** Depends on: 5. Deliverable: each Quad screen has independently editable English/Japanese content and shared functional behavior.
  - [x] **6.1. Equipment and filament steps.** Depends on: 5.4. Move prerequisite and tuning prose/checklist labels into parallel TSX content; pass shared reactive checkbox controls/handlers into the content where independent placement is needed. Confirm gating, the skip-equipment preference, Back/Next, and the existing step count remain unchanged.
  - [x] **6.2. Slice, print, and locate steps.** Depends on: 6.1. Move rich instructions, STL link label, image captions/alt text, and inline cautions into the locale-specific page JSX. Keep the same STL URL/download filename, image assets, and step transitions; allow each language to reorder explanatory text and figures within its screen.
  - [x] **6.3. X and Y/A/B measurement steps.** Depends on: 6.2. Move prose, field legends, existing-value summaries, and figure descriptions into page content; use shared `BeamFields` controls and validation for both languages. Verify all eight Quad measurements keep their IDs, warnings, values, and per-axis handlers when switching mid-step.
  - [x] **6.4. Printer naming and Quad result.** Depends on: 6.3. Localize duplicate/overwrite confirmation, name errors, storage-failure factor advice, result instructions, percent warnings, and image descriptions. Keep the factor save/overwrite calculation and Finish behavior shared; switch languages on an active duplicate warning and on a displayed result without saving a second time.
  - [x] **6.5. Regress the Quad flow.** Depends on: 6.4. Run a full Quad calibration in both locales using English placeholders, including invalid inputs, an existing-printer overwrite, result screen, Back restrictions, Exit, and refresh/resume mid-flow. Run `pnpm test` and `pnpm build`; no formulas, field defaults, numeric formatting, or persistence semantics may change.

- [x] **7. Convert the Single calibration flow.** Depends on: 6. Deliverable: the second flow uses the same locale and shared behavioral rules as Quad.
  - [x] **7.1. Printer selection and filament steps.** Depends on: 6.5. Localize headings, empty-printer guidance, picker accessible text, and tuning prose in separate JSX content. Keep saved-printer selection, no-printer gating, checkboxes, and transitions shared and unchanged.
  - [x] **7.2. Slice and print steps.** Depends on: 7.1. Move STL link copy, instructions, captions, alt text, and cautions into parallel page JSX; keep images and STL/download filename shared with the current app. Check each locale can reorder instructions without affecting step navigation.
  - [x] **7.3. Measure and result steps.** Depends on: 7.2. Localize guidance, measurement field labels, missing-printer error, current-XY warnings, result explanations, and copy output. Reuse the localized shared guides/fields; preserve printer-factor lookup, Single calculation, percentage formatting, validation, and Finish behavior.
  - [x] **7.4. Regress the Single flow.** Depends on: 7.3. Complete it in both locales with an imported/saved printer; test missing-printer, invalid input, result, Exit, and refresh/resume. Switch mid-measurement and while an error is visible; verify values persist and already-visible messages update. Run `pnpm test` and `pnpm build`.

- [x] **8. Validate and document the implementation milestone.** Depends on: 7. Deliverable: no unintended untranslated UI surfaces, responsive/accessible behavior, and reproducible verification notes.
  - [x] **8.1. Audit both locales.** Depends on: 7.4. Revisit the task 1.2 inventory and search the runtime UI for hard-coded English in pages, shared components, helper errors, aria/title/alt/caption text, progress, dialogs, and result states. Confirm every visible string has a separately editable Japanese placeholder and that each screen's required controls remain reachable in either content order. Do not localize metadata, URLs, downloaded filenames, JSON keys, printer names, or numeric formats.
  - [x] **8.2. Check Japanese-ready styling and accessibility.** Depends on: 8.1. Review current font stack (already includes Japanese-capable fallbacks), line breaking, overflow, controls, tables, progress, popover, and long instructions at phone and desktop widths. Add only necessary CSS to accommodate Japanese text. Test keyboard/focus and screen-reader names, and verify `html[lang]` updates after switching.
  - [x] **8.3. Verify supported browser journeys.** Depends on: 8.2. On available current desktop Chrome/Safari and mobile Chrome/Safari (plus other mainstream evergreen browsers available locally), check first-load detection, saved preference, blocked-storage session switching, each placement of the switcher, both flows, dialogs, active warnings, and printing/image links. Record unavailable browser/device checks rather than claiming they passed. (Chrome desktop + 360px mobile viewport exercised; Firefox/WebKit/mobile Safari/Edge and screen-reader passes recorded as outstanding in `README.md`.)
  - [x] **8.4. Close the implementation milestone.** Depends on: 8.3. Document in `truss-webui/README.md` where page-like locale copy and shared messages are edited, how to add a locale, and the manual translation/release gate. Run `pnpm test`, `pnpm build`, and `git diff --check`; review changes to ensure printer import/export and calibration persistence/data are unchanged. Explicitly label Japanese English text as placeholders, not release-ready copy.

- [ ] **9. Complete the separate public-release translation gate.** Depends on: 8. Deliverable: reviewed Japanese UI copy; this stage depends on the maintainer supplying the translations.
  - [ ] **9.1. Replace Japanese placeholders.** Depends on: 8.4. Manually translate every Japanese page-like TSX screen, shared message, validation/import/storage error, dialog, caption/alt text, and accessible label; retain native language names. Existing English instructional screenshots may remain. Do not alter calculations or field parsing while translating.
  - [ ] **9.2. Review translated journeys.** Depends on: 9.1. Walk Home/About/Manage printers, full Quad and Single flows, result states, error/warning dialogs, and image zoom in both languages. Check Japanese copy for accuracy and unintended English leftovers and fix clipping/wrapping on desktop and phone widths; confirm all interactive slots remain present if content was reordered.
  - [ ] **9.3. Approve release.** Depends on: 9.2. Rerun `pnpm test`, `pnpm build`, `git diff --check`, and the supported-browser smoke checks. Confirm an explicit choice persists, browser fallback follows preference order, mid-flow switching preserves progress, all visible errors update, and no Japanese English placeholders remain except intentionally shared image text, proper names, technical terms, and filenames.
