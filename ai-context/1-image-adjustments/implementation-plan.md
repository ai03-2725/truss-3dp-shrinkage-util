# Generated guide images — implementation plan

Source of truth: [PRD.md](./PRD.md). Work in `truss-webui/` unless a path says otherwise. **Depends on** names prerequisite task IDs; a numbered parent task is complete only when its subtasks are complete. Follow the order below. The final task is the release gate; no task adds new app features.

- [x] **1. Confirm the image and build baseline.** Depends on: none. Deliverable: a known-good starting point and a clear inventory of assets to migrate.
  - [x] **1.1. Inventory assets and references.** Depends on: none. Compare `Documentation/Images/`, the tracked files in `truss-webui/src/assets/images/`, and the 30 image imports in `truss-webui/src/lib/assets.ts`. Note that `truss-dual.png` is not imported. Check for duplicate basenames that would collide as `.avif` and find any image references outside `assets.ts` that need migration. Do not touch the documentation originals or STL files.
  - [x] **1.2. Record the baseline.** Depends on: 1.1. Run `pnpm test` and `pnpm build` from `truss-webui/`; inspect `package.json`, `.gitignore`, `vite.config.ts`, and `README.md`. Record failures before making changes and confirm Vite's imported asset URLs currently support nested-path builds and embedding.

- [x] **2. Add a repeatable AVIF generator.** Depends on: 1. Deliverable: one explicit command that creates missing images from the repository originals without modifying existing outputs.
  - [x] **2.1. Choose the smallest reliable encoder and location.** Depends on: 1.2. Use an AVIF-capable encoder available after the project's normal dependency install (for example, `sharp`, not an undocumented globally installed CLI); add only the needed development dependency and update `truss-webui/pnpm-lock.yaml`. Put a small generation script under `truss-webui/scripts/` and write outputs to `truss-webui/src/assets/images/` so existing Vite imports can retain their relative path. Resolve `../../Documentation/Images/` from the script's location, not the caller's working directory.
  - [x] **2.2. Convert the images.** Depends on: 2.1. Keep a simple list of required source filenames corresponding to the 30 app images; check each source exists even if an output is already present, so deleting an original cannot silently pass. Ignore the unused Dual image and `.DS_Store`. Use AVIF quality 60, keep orientation and aspect ratio, resize only when the longest dimension exceeds 2560 px, and never enlarge a smaller image. Use each source basename plus `.avif` as the output name; reject any duplicate basenames in the list rather than overwriting. Preserve `Documentation/Images/` unchanged.
  - [x] **2.3. Make reruns and failures safe.** Depends on: 2.2. Skip an existing destination without re-encoding it. Fail with the affected path and a nonzero exit on a missing/unreadable required source or an encode/write error; do not leave a failed or partial output that a later run would mistake for a completed image (for example, write to a temporary file, then rename on success and clean up on failure). Avoid checksum, timestamp, or source-change invalidation: sources are assumed immutable.
  - [x] **2.4. Expose the command.** Depends on: 2.3. Add `generate:images` to `truss-webui/package.json` so `pnpm generate:images` works from `truss-webui/`, including when launched from a full-repository checkout by a host build. Run it once and confirm the expected `.avif` files appear without changing the source files.

- [x] **3. Verify generator behavior before switching imports.** Depends on: 2. Deliverable: runnable, focused checks that prevent incorrect output and broken clean-checkout builds.
  - [x] **3.1. Check format and dimensions.** Depends on: 2.4. Add a small check using Node's existing `node:test`/assert setup (and the chosen encoder's metadata API if available) or another repeatable project command. Confirm outputs are AVIF; compare widths/heights against both a >2560 px source and an already-small source; assert or inspect the encoder's quality-60 setting (it may not be readable from output metadata) and check orientation/aspect ratio. Avoid a new test framework or tracked generated fixtures.
  - [x] **3.2. Check skipping and recovery.** Depends on: 3.1. Capture the output's bytes or modification time, rerun the generator, and verify no replacement; remove one generated output, rerun, and verify only that output is recreated. Exercise a missing source and an encoder/write failure safely (e.g. in a temporary fixture or by temporarily moving and restoring a source) and verify a useful nonzero error and no partial destination. Make sure tests leave tracked originals intact.
  - [x] **3.3. Wire the focused checks into `pnpm test`.** Depends on: 3.2. Update the existing test script to include the generator checks alongside `src/**/*.test.ts`; keep existing app tests passing. Leave full browser/host verification to task 5 instead of adding a test framework.

- [x] **4. Switch the app to generated assets.** Depends on: 3. Deliverable: `dev`, `build`, and `test` work from a clean checkout without tracked image duplicates.
  - [x] **4.1. Run generation before package entry points.** Depends on: 3.3. Update the `dev`, `build`, and `test` scripts in `truss-webui/package.json` to explicitly run the generator first. Preserve the existing Vite, TypeScript, and Node test behavior; do not rely on package-manager-specific pre/post hooks unless verified for the documented package managers. Leave `preview` serving an already-built `dist/`.
  - [x] **4.2. Update app imports.** Depends on: 4.1. Change the image import extensions in `truss-webui/src/lib/assets.ts` to `.avif` while retaining every exported `img` key and Vite-managed asset URL. Do not change `Guide.tsx`, `Lightbox.tsx`, image alt text, flow screens, or STL imports unless a real regression requires it.
  - [x] **4.3. Remove tracked duplicates and ignore outputs.** Depends on: 4.2. Remove the tracked JPG/PNG files under `truss-webui/src/assets/images/` from git, retaining the originals under `Documentation/Images/`. Add a targeted ignore rule for generated images (and any temporary outputs) to `truss-webui/.gitignore`. Check `git status`/`git check-ignore` to ensure the AVIF files are untracked/ignored while source images and STLs remain tracked.
  - [x] **4.4. Confirm the migration compiles.** Depends on: 4.3. Run `pnpm test` and `pnpm build`. Check that the build emits the AVIFs used by the app in `dist/` and that no legacy app JPG/PNG image URLs remain; fix missing imports before proceeding.

- [x] **5. Document and validate delivery.** Depends on: 4. Deliverable: reproducible developer and host instructions plus evidence against the PRD acceptance criteria.
  - [x] **5.1. Document the workflow.** Depends on: 4.4. Update `truss-webui/README.md` with the full-repository prerequisite, `pnpm generate:images`, automatic generation on `dev`/`build`/`test`, and the requirement for an embedding host to run the explicit command **before** its own build. Explain that outputs are ignored, originals stay in `Documentation/Images/`, existing outputs are skipped, and changed settings require deleting the affected outputs. State that deployed `dist/` does not need the originals.
  - [x] **5.2. Verify each command from a clean-output state.** Depends on: 5.1. With dependencies installed, remove only the ignored generated outputs and separately run `pnpm test`, `pnpm build`, and `pnpm dev` from that state, clearing generated outputs between runs. Confirm each generates required images without a manual preliminary step; stop the dev server after verifying it serves an image. Recheck the rerun/missing-output/failure-path cases from task 3 if they were not automated.
  - [x] **5.3. Verify delivery paths and visual quality.** Depends on: 5.2. Serve a production `dist/` build under a nested URL without exposing `Documentation/Images/`; confirm Quad and Single images load and thumbnails/enlarged zoom views retain readable diagram text. For an embedding host build, run `pnpm generate:images` first and confirm its Vite-managed image URLs work; if an actual host is unavailable, record that verification as outstanding. Smoke-check current desktop/mobile browsers available locally; do not claim coverage for browsers not tested.
  - [x] **5.4. Release gate.** Depends on: 5.3. Rerun `pnpm test`, `pnpm build`, and `git diff --check`; inspect the diff/status for unintended changes to originals, documentation links, STL assets, alt text, or calibration logic. Confirm all required outputs meet the PRD's sizing/format settings, repeat runs leave existing outputs alone, and no generated or legacy web-app images are tracked. Record any unverified manual/browser checks before marking the update complete.
